# Сайт детского сада «Ботаканым»

Django (API + админка) + React (публичный сайт). Два языка — казахский и русский, версия для слабовидящих, вход для сотрудников.

```
backend/    Django: модели, API, админка, вход сотрудников, раздел оплат (payments/), медкабинет (medjournal/)
frontend/   React (Vite): все страницы сайта
deploy/     nginx и systemd для VPS
```

## Как это устроено

- **Публичный сайт** — React. Адреса вида `/kk/parents`, `/ru/parents`. По умолчанию открывается казахская версия.
- **Содержимое** сотрудники вводят в админке Django (`/manage/`): тексты разделов, документы, новости, педагоги, вакансии, FAQ.
- **Вход для сотрудников** — `/kk/staff/login`. Сессия Django (cookie), без токенов в браузере. После входа — кабинет: новые обращения с сайта и быстрые ссылки в админку. Та же сессия действует в админке, повторно входить не нужно.
- Войти может только пользователь со статусом «Персонал». Права задаются группой «Редакторы сайта».

## Табель и оплаты

`/payments/` — табель, оплаты, долги, контакты родителей. Доступ — только суперпользователь со статусом персонала.

- Данные из e-orda — закладки «Табель» и «Родители» (кнопка «Загрузить из e-orda» в разделе, там же инструкция). Закладка открывает окно `/payments/eorda/`, через него данные и сохраняются: нужен вход на сайт под администратором и разрешённые всплывающие окна для e-orda. Открытый табель обновится сам.
  - «Табель»: откройте табель в e-orda и нажмите закладку.
  - «Родители»: работает на любой странице e-orda. Контакты (с отметкой, кто отец и кто мать — `Gender` 1/2) и адрес ребёнка (`ChildAddress`) берутся из карточек детей (`GetPupil`), номер и дата подписания договора — из списка договоров ребёнка (`GetContractGridForPupil`, берётся последний). Детей закладка находит по группам из табеля, группам, открытым на странице, и группам из самих карточек (`KindergardenGroupId`). id ребёнка и группы в табеле совпадают с id в e-orda. Если карточка или список договоров не открылись, прежние данные ребёнка остаются.
  - Код закладок — `backend/payments/templates/payments/_bookmarklets.js`, он встроен в страницу табеля. После его изменения закладки нужно перетащить заново; старые закладки продолжают работать, окно сайта подскажет, что закладка устарела.
- Оплату и отметки дней правят в карточке ребёнка — изменения сохраняются сразу, отметки попадают в журнал изменений.
- Оплату можно отмечать и прямо в табеле: в колонке «Оплата» у правого края — способ (наличные или онлайн) и внесённая сумма. Способ без суммы записывает сумму к оплате (Итого), «—» снимает отметку и обнуляет внесённое. Над таблицей — фильтр по оплате и итоги: сколько детей оплатили наличными и онлайн и на какую сумму.
- Массовые действия: выберите детей галочками (галочка в заголовке — все в списке с учётом поиска и фильтра) → панель внизу: отметить оплату наличными или онлайн, снять отметку, задать ежемесячную сумму или вернуть сумму по умолчанию. Меняется только открытый месяц, перед сохранением — подтверждение.
- Многодетные семьи отмечаются вручную: галочка «Многодетная семья» в карточке ребёнка или «Многодетная → Отметить / Снять» в панели выбранных детей в табеле (а также Админка → «Воспитанники»). Отметка хранится у воспитанника (находится по id и по ИИН), поэтому остаётся после «Очистить месяц» и новой загрузки табеля из e-orda. Ежемесячная оплата по умолчанию — 51 000 ₸ многодетной семье и 60 000 ₸ остальным (`LARGE_FAMILY_MONTHLY` и `DEFAULT_MONTHLY` в `payments/models.py`); сумма, заданная вручную в карточке или массово, важнее. Связь с родителями (контакты из e-orda, закладка «Родители») показывает братьев и сестёр — в карточке ребёнка и на странице «Родители».
- Миграция `payments.0007` оставляет прошлым месяцам прежнюю сумму по умолчанию 51 000 ₸, чтобы долги задним числом не изменились; новые суммы действуют с месяца, в котором выполнена миграция. В этом месяце и позже сохранённые ранее 51 000 ₸ снова становятся «по умолчанию». Миграция `payments.0008` убирает автоматическое определение многодетных: остаются только отмеченные вручную.
- Админка → «Табель и оплаты». Квитанции, которые раньше загружал Telegram-бот, остались там только для просмотра («Квитанции (архив)»).

### Медицинская документация

`/payments/med/` — 17 журналов медкабинета и пищеблока (приложение `backend/medjournal/`, список журналов — в его `journals.py`). Кнопка «Медицинская документация» — в табеле, ссылка — в кабинете сотрудника.

- Дети — из табеля: модель «Воспитанники» (одна запись на ребёнка) заполняется при каждой загрузке табеля. У выбывших снимите галочку «Посещает детский сад» (Админка → «Воспитанники») — из списков они пропадут, записи останутся.
- В новой записи после выбора ребёнка сами заполняются поля «Мать», «Отец», «Домашний адрес» и «Дата поступления» (= дата подписания договора) — данные из закладки «Родители». Работает в любом журнале, где есть поля `mother`, `father`, `address`, `admission_date` (список — `CHILD_FACT_FIELDS` в `medjournal/views.py`). Исправленное вручную не перезаписывается.
- Кнопка «Заполнить всех» (медкарты, паспорт здоровья — журналы, где на ребёнка одна запись и кроме ребёнка обязательных полей нет): заводит запись каждому посещающему ребёнку, у которого её ещё нет, и дополняет пустые поля существующих записей данными из e-orda. Неизвестные поля остаются пустыми, заполненное вручную не меняется; перед заполнением — страница подтверждения. Нужны права на добавление и изменение записей журнала.
- Доступ — по правам Django на модели `medjournal`: администратор видит всё; медсестре или повару можно выдать права только на нужные журналы (статус персонала + права/группа). Без прав журнал не показывается, страница отвечает 403.
- Шапка и подпись печатных форм — `MEDJOURNAL_ORG_NAME` (по умолчанию «Детский сад «Ботаканым»») и `MEDJOURNAL_ORG_HEAD` в `backend/.env`.
- Журналы с детьми разделены по группам (группа ребёнка — из табеля): вкладки групп над списком, в фильтре и в форме дети сгруппированы, печать — по выбранной группе («Группа: …» в шапке) или по всем с колонкой «Группа».
- Массовые действия в списке журнала: отметьте записи галочками (или все на странице, затем «Отметить все записи по фильтру») → «Изменить отмеченные» (одно поле во всех записях, кроме ребёнка; если новое значение нарушает правило журнала хоть в одной записи, не меняется ничего) или «Удалить отмеченные». Оба действия — через страницу подтверждения; нужны права на изменение/удаление записей журнала.
- «Заполнить период» в новой записи (журналы с обязательной датой и без вложенных таблиц): укажите последний день — те же данные сохранятся отдельной записью на каждый день с даты записи по него включительно, по умолчанию без субботы и воскресенья. У даты со временем время остаётся прежним. Не больше года за раз.
- Журналы 12, 17 и 16 ведутся и печатаются по утверждённым формам 1, 2 и 3: графы и их названия как в форме, нумерация граф с 1 без «№ п/п», «Форма N» в углу, примечание к форме под таблицей, подписи — в графах (без общей строки подписей). Задаётся полями `form`, `footnote`, `footnote_column` в `journals.py`.
- «Скачать Word» — в списке журнала, на его печатной форме и на печатной форме записи (медкарта, паспорт здоровья и т. п.): файл .docx с тем же содержимым, что на печати, с учётом фильтров и группы. Собирается в `medjournal/word.py` (библиотека `python-docx`).
- Строка «Начат … Окончен …» в печати журнала: даты вводятся над печатной формой (нужно право изменять журнал), сохраняются для каждого журнала и сразу появляются в шапке. Пустая дата печатается как «___» __________ 20__ г. — вписать от руки.
- Оформление страниц — `backend/templates/medjournal/base.html`.

### Переезд со старой системы табеля

```bash
# 1. Остановить старую систему и Telegram-бота — чтобы после копии базы в неё ничего не записалось
sudo systemctl disable --now timesheet botpay
sudo install -m 644 /home/ubuntu/timesheet_project/db.sqlite3 /tmp/timesheet_old.sqlite3

# 2. Перенести данные (только в пустой раздел; старую базу не меняет)
cd /var/www/kindergarten-site/backend
sudo -u www-data ../venv/bin/python manage.py migrate
sudo -u www-data ../venv/bin/python manage.py import_timesheet /tmp/timesheet_old.sqlite3

# 3. Отдать домен сайту
sudo rm /etc/nginx/sites-enabled/botakanym
sudo cp ../deploy/nginx-kindergarten-site.conf /etc/nginx/sites-available/kindergarten-site
sudo nginx -t && sudo systemctl reload nginx && sudo systemctl restart kindergarten-site
```

Пользователи старой системы не переносятся.

### Telegram-бот больше не используется

Если бот уже работал на сервере, отключите его. Миграция `payments.0005` удаляет таблицы подписок родителей и пользователей Telegram (квитанции остаются в архиве) — перед `migrate` сделайте бэкап базы.

```bash
sudo systemctl disable --now botpay
sudo rm /etc/systemd/system/botpay.service && sudo systemctl daemon-reload
# папку /home/ubuntu/telegram_bot можно удалить; строку IMPORT_API_KEY из backend/.env — тоже
```

### Картинка по времени года и «Документы для зачисления»

- Картинка с верблюжатами на главной, рядом с режимом работы, — `frontend/src/components/SeasonScene.jsx`, слои — `frontend/src/assets/seasons/`. Картинка и анимация (снег, лепестки, бабочки, дождь с листьями) меняются по времени года на устройстве посетителя: декабрь–февраль — зима, март–май — весна, июнь–август — лето, сентябрь–ноябрь — осень. При настройке «уменьшить движение» анимация останавливается, при «Изображения: скрыть» картинка убирается.
- Перечень документов для зачисления (в разделе «Родителям») — `frontend/src/components/ParentsDocuments.jsx`, тексты на двух языках — в `ParentsDocuments.content.js` рядом. После правки нужна новая сборка (`npm run build`). В версии для слабовидящих блок берёт цвета выбранной схемы.

## Локальный запуск

```bash
# 1. Backend
cd backend
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
echo "DJANGO_DEBUG=1" > .env
python manage.py migrate
python manage.py setup_site          # разделы + группа «Редакторы сайта»
python manage.py createsuperuser
python manage.py runserver

# 2. Frontend (в другом терминале)
cd frontend
npm install
npm run dev                           # http://localhost:5173
```

Vite проксирует `/api`, `/media`, `/static`, `/manage`, `/payments` на Django (`http://127.0.0.1:8000`, другой адрес — переменная `DJANGO_URL`), поэтому cookie и CSRF работают так же, как на сервере.

## Как добавить сотрудника, который будет входить на сайт

1. Админка → Пользователи → Добавить. Пароль не короче 10 символов.
2. Поставить галочку «Статус персонала».
3. Добавить в группу «Редакторы сайта». Суперпользователя делать не нужно.

## Развёртывание на сервер (Ubuntu 22.04+)

Сайт живёт в `/var/www/kindergarten-site`: свой venv, служба gunicorn и server-блок nginx. Всю настройку на сервере делает `deploy/deploy.sh` — он же обновляет сайт.

**0. Домен.** У регистратора направьте `botakanym.edu.kz` и `www.botakanym.edu.kz` (A-записи) на IP сервера, при IPv6 — и AAAA-записи. Без этого не выдастся HTTPS-сертификат, а вход сотрудников работает только по HTTPS.

**1. Сборка и архив — на своём компьютере** (PowerShell, из папки проекта):

```powershell
cd frontend; npm run build; cd ..
tar -czf ..\botakanym-deploy.tar.gz --exclude=venv --exclude=__pycache__ --exclude=.cache --exclude=.env --exclude=db.sqlite3 --exclude=staticfiles --exclude=media backend deploy frontend/dist
scp ..\botakanym-deploy.tar.gz ubuntu@<IP-сервера>:/tmp/
```

В архив не попадают `.env`, база и загруженные файлы — на сервере они свои и при обновлении не перезаписываются.

**2. Установка или обновление — на сервере** (`ssh ubuntu@<IP-сервера>`):

```bash
sudo mkdir -p /var/www/kindergarten-site
sudo tar -xzf /tmp/botakanym-deploy.tar.gz -C /var/www/kindergarten-site
sudo bash /var/www/kindergarten-site/deploy/deploy.sh
```

Скрипт ставит пакеты, создаёт `backend/.env` со случайным секретным ключом, перед миграциями копирует базу в `backups/`, собирает статику и перезапускает службу. Настройки nginx копируются только при первой установке, чтобы не затереть SSL от certbot.

**3. Только при первой установке:**

```bash
sudo -u www-data /var/www/kindergarten-site/venv/bin/python /var/www/kindergarten-site/backend/manage.py createsuperuser
sudo certbot --nginx -d botakanym.edu.kz -d www.botakanym.edu.kz
```

Дальше: войдите на `https://botakanym.edu.kz/kk/staff/login`, заполните «Настройки сайта» в админке и загрузите табель и контакты родителей закладками из e-orda.

Проверка: `systemctl status kindergarten-site`, журнал — `journalctl -u kindergarten-site -n 50`.

Если меняете `DJANGO_ADMIN_URL`, поменяйте путь и в nginx (`location ~ ^/(api|manage|payments)/`) и в `vite.config.js`.

Бэкап: база (`backend/db.sqlite3` или дамп PostgreSQL) + папка `media/`. Копии базы перед каждым обновлением — в `backups/`.

## Требования закона: что сделано в коде, а что — на вас

**Сделано в коде**
- Казахский и русский: все подписи интерфейса и каждое поле содержимого в двух версиях; язык в адресе и в `<html lang>`.
- Актуальность: у документов и разделов видна дата публикации/обновления.
- Фото детей: новость с фото нельзя сохранить без галочки о согласии родителей; у каждого фото обязательное описание на двух языках. Из фото удаляются EXIF-данные (там бывают GPS-координаты).
- Фото сотрудников показываются, только если отмечено «Показывать фото».
- Обращения: обязательное согласие на обработку персональных данных; обращения видят только сотрудники с правом просмотра; защита от ботов и лимит 5 обращений в час с одного адреса.
- Вход сотрудников: CSRF-защита, сессия на 8 часов, лимит 5 попыток входа в минуту, одинаковое сообщение при неверном логине и пароле.
- Доступность: версия для слабовидящих (шрифт 100/125/150%, три контрастные схемы, отключение изображений, увеличенный интервал), переход к содержимому, видимый фокус, навигация с клавиатуры, подписи ко всем полям, таблицы с заголовками, уважение к настройке «уменьшить движение».

**На вас**
- Сверить сайт с полным текстом СТ РК 2191-2023. В коде реализованы общепринятые практики доступности, но конкретные пункты стандарта нужно проверить по документу.
- Хранить бумажные согласия родителей — галочка в админке лишь подтверждает, что они есть.
- Не загружать закрытые сведения: медкарты, ИИН, личные телефоны, данные детей в документах.
- Регулярно обновлять меню, отчёты, вакансии.
- Опубликовать политику обработки персональных данных (текст — от юриста или отдела образования).
